# Target Authority Map

This document is the implementation map for the
[`2026-08-29 product redesign master plan`](../plans/2026-08-29-lucid-fin-product-redesign-master-plan.md).
It exists to prevent the refactor from creating parallel sources of truth.

## Aggregate ownership

| Aggregate             | Owns                                                                          | Must not own                                             |
| --------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------- |
| Project               | Workspace identity, lifecycle, defaults, role bindings                        | Film order, provider secrets, generated media bytes      |
| Chat / Run            | Transcript, accepted input, frozen policy/capability snapshot, task execution | Production facts, Canvas layout, reusable assets         |
| Production            | Typed creative facts and semantic relations                                   | Spatial layout, editorial order, provider attempts       |
| Canvas                | Name/lifecycle, placement, geometry, groups, annotations, saved views         | Narrative order, generated candidates, task state        |
| Sequence              | Ordered scenes/shots/clips and clip edit parameters                           | Canvas geometry, provider history, mutable global assets |
| Generation / Result   | Request, attempt, artifact, receipt, usage, validation, provenance            | A second creative node or editable film order            |
| Assessment / Decision | Evidence, score, confidence, selected/approved/rejected/refine history        | Generated bytes, implicit destructive replacement        |
| Global Asset Library  | Stable entity identity, immutable revisions, immutable media versions         | Live mutation of Project bindings                        |
| Project Asset Binding | Exact pinned global revision or explicit local fork link                      | Floating latest-version semantics                        |
| Provider Connection   | Endpoint, authentication strategy, Keychain handle, health                    | Model-specific project selection                         |
| Provider Profile      | Capability, model, defaults, quote/pricing support, status                    | Secret material                                          |
| Delivery              | Export policy and frozen manifest derived from an exact Sequence revision     | An independent reorderable item list                     |

## Mandatory invariants

1. A Canvas geometry mutation cannot change a Sequence revision or hash.
2. A Sequence mutation cannot change a Canvas revision or hash.
3. Production relations do not contain an ordinal used by playback or export.
4. Delivery freezes exact Sequence items/results; it does not expose an independent reorder mutation.
5. Candidate views are derived from `targetRef + generation slot` over GeneratedResult, Assessment,
   and Decision records. No Candidate table exists.
6. At most one active `selected` result exists per target and slot. `approved` is a distinct decision.
7. A downstream operation resolves the selected result for its required slot or pauses according to the
   frozen Run policy; it never guesses.
8. Upstream changes mark dependent results stale through recorded input revisions/hashes.
9. A Project asset binding pins one immutable Library revision. Publishing a new revision never updates
   bindings implicitly.
10. Credentials stay in Electron main/Keychain. Renderer, storage records, logs, and AI-visible payloads
    contain only redacted handles and status.
11. Every paid operation has a current quote and fits the frozen hard budget before submission.
12. Full Auto cannot waive credential, hard-budget, destructive, overwrite, upload, or external-sharing
    protection.

## Run snapshot

Run acceptance freezes:

- Project, selected Canvas, Sequence, Production, and Asset-binding revisions/hashes;
- exact Provider Profile/model allowlist and role bindings;
- execution preset, permission ceiling, hard budget, spend approval, selection mode, confidence floor,
  retry/attempt ceilings, parallel-operation limit, and granted export destination;
- exact Skill, Catalog, and Shot Recipe versions; and
- causation links to the user message and attachments.

Later Settings or global Asset changes do not rewrite an accepted Run. CAS conflicts require reread and
replanning; last-write-wins is prohibited.

## Delivery freeze

Freezing a Delivery manifest reads one exact Sequence revision and resolves each Clip to one exact
GeneratedResult or imported media version. The manifest records the Sequence item identity, ordinal at
freeze, trim/transition/audio values, content hashes, and provenance. It remains reproducible after
later edits. If a current selected result or Sequence changes, the old manifest is marked historical or
stale but is never mutated.
